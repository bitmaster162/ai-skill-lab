Пять проектов Роберта Думаняна с открытыми репозиториями и проверяемым объёмом работ. Это проекты наставника, не работы учеников и не клиентские кейсы.

VISUAL AI · PUBLIC REPORESEARCH / OFFLINE TESTABLE

01VisionAssist

Визуально-семантический слой для evidence-grounded observations, competing hypotheses, counterevidence, uncertainty и явной human-AI revision.

01ДоказательствоПубличный репозиторий фиксирует 75-case corpus: 60 market chart cases + 15 deterministic visual-control cases, offline harness, scorer и proof checklist.

02Граница claimsREADME не заявляет calibration, human-AI uplift, natural-scene generality или production value.

MEMORY · PUBLIC REPOLOCAL-FIRST / OPEN SOURCE

02ContinuityOS

Durable memory и continuity layer для AI-агентов и людей: canon, frontiers, open loops, checkpoints и handoff context.

01ДоказательствоПубличный репозиторий и PyPI package; core memory работает локально на SQLite, поддерживает CLI, Python API, MCP и импорт AI-history из нескольких провайдеров.

02Граница claimsDemo доказывает bounded persistence через новый процесс, а не поведенческую идентичность модели или production security.

GitHub ↗
AGENT GOVERNANCE · PUBLIC REPODETERMINISTIC REFERENCE

03BitEvo Agent Authority

Публичный reference package семи ворот Agent Authority & Evidence для проверки одного action-capable workflow.

01Доказательствоspec/gates.json, локальный deterministic evaluator, fail-closed validation и regression tests; package source-bound к публичной BitEvo реализации.

02Граница claimsНе выдаёт trust/safety score, не сертифицирует систему, не исполняет внешние действия и не запрашивает credentials.

GitHub ↗
AI PRODUCT · PUBLIC REPOPUBLIC PRODUCT / EVIDENCE SURFACE

04BitEvo Agent Site

Публичный продукт для authority-first AI-agent engineering, где SOURCE, BUILD, DEPLOYMENT, READBACK и EXTERNAL EFFECT разделены как разные классы доказательств.

01ДоказательствоAstro site с provider-bound build receipts, deterministic release gates, CSP hash allowlist и раздельными Vercel / Cloudflare provider paths.

02Граница claimsProduction promotion отделён от build/readback; публичный repository прямо фиксирует can_trade=false и capital_permission=DENY.

GitHub ↗
CONTROL STACK · PUBLIC REPOVALIDATION-ONLY

05TRIAXIS

Versioned governance/control stack с deterministic validation assets для policy binding, external witnesses, execution reconciliation и rollback detection.

01ДоказательствоПубличный репозиторий содержит executable validation harnesses для signed policy heads, quorum, execution ledger, provider reconciliation и completion witnesses.

02Граница claimsRepository прямо указывает: это не production gateway; validation results не доказывают production exactly-once behavior или complete mediation.

Ниже — учебные примерные форматы, а не заявления о конкретных клиентах или учениках. Весь контент доступен даже без JavaScript; фильтр работает только локально в браузере и ничего не отправляет наружу.

9 / 9 проектов показаноЛокальный фильтр · данные не отправляются
01 · ИССЛЕДОВАНИЕ8–13

01Детектив фактов

Тема → 3+ источника → таблица утверждений → короткая презентация «что подтвердилось / что нет».

01ЗадачаОтделить проверяемый факт от красивого ответа.

02Роль ИИПомогает сформулировать поисковые запросы, сравнить версии и организовать находки.

03Проверка человекомОткрывает источники, отмечает противоречия и объясняет, почему выводу можно доверять.

04Готовый результатТаблица источников + карта утверждений + мини-презентация.

02 · CREATE8–13

02Мир и персонаж

Описание персонажей, визуальные правила, раскадровка и итоговая мини-история с явным разделением своей идеи и ИИ-помощи.

01ЗадачаПревратить идею в последовательную систему мира и персонажей.

02Роль ИИПредлагает варианты, референс-направления и помогает проверять внутреннюю логику.

03Проверка человекомВыбирает художественные решения и может объяснить, что придумал сам и где использовал ИИ.

04Готовый результатОписание персонажей + раскадровка + итоговая история.

03 · LOGIC8–13

03Мини-игра

Правила, состояния, простая логика и прототип. Ребёнок показывает, почему система работает именно так.

01ЗадачаСобрать маленькую работающую систему вместо одноразовой генерации.

02Роль ИИПомогает разложить механику на правила, состояния и тестовые сценарии.

03Проверка человекомПроверяет причинность, чинит сломанные правила и защищает логику проекта.

04Готовый результатПравила игры + карта состояний + игровой прототип.

04 · УЧЁБА14–18

04Система исследования

Шаблон исследования: вопрос, источники, тезисы, проверка, итоговая записка и презентация.

01ЗадачаСделать исследование повторяемым процессом, а не случайным набором вкладок.

02Роль ИИРасширяет поиск, группирует доказательства и помогает видеть конфликтующие версии.

03Проверка человекомОценивает качество источников и принимает аргументированный вывод.

04Готовый результатШаблон исследования + карта доказательств + записка + презентация.

05 · СБОРКА14–18

05Прототип ИИ-помощника

Простой ассистент или рабочий процесс под реальную задачу: вход, правила, результат, сценарии сбоев и README.

01ЗадачаПревратить задачу в спецификацию, которую можно протестировать.

02Роль ИИПомогает с декомпозицией, правилами промптов и системы, связующим кодом и тестовыми случаями.

03Проверка человекомОпределяет границы, проверяет ошибки и решает, где автоматизация должна остановиться.

04Готовый результатПрототип + тестовые сценарии + README + карта отказов.

06 · ПРОДУКТ14–18

06Мини-продукт

Проблема пользователя, прототип, тестовые сценарии, ограничения и короткая демонстрация.

01ЗадачаПроверить продуктовую гипотезу работающим артефактом.

02Роль ИИПомогает исследовать варианты, собрать интерфейс и ускорить итерации.

03Проверка человекомОграничивает объём работ, разговаривает с пользователем и принимает продуктовые решения.

04Готовый результатРаботающий прототип + контрольный список проверок + демонстрация + известные ограничения.

07 · РАБОЧИЙ ПРОЦЕССAdults

07Личный исследовательский процесс

Повторяемая система поиска, сопоставления источников, синтеза и проверки.

01ЗадачаСократить путь от вопроса до решения сохранив дисциплину работы с источниками.

02Роль ИИСобирает варианты, сравнивает доказательства и готовит структуру краткого решения.

03Проверка человекомПроверяет первоисточники, допущения и владеет финальным решением.

04Готовый результатПовторяемый рабочий процесс + карта источников + шаблон краткого решения.

08 · АВТОМАТИЗАЦИЯВзрослые / бизнес

08Прототип рабочего процесса

Ассистент или автоматизация для одного повторяемого процесса с назначенным владельцем и запасным вариантом.

01ЗадачаАвтоматизировать один процесс так, чтобы оставался понятный владелец и откат.

02Роль ИИВыполняет повторяемые трансформации, маршрутизацию и черновую обработку.

03Проверка человекомОпределяет разрешения, сценарии отказа, критерии приёмки и запасной вариант.

04Готовый результатWorkflow + acceptance tests + handoff + rollback path.

09 · ПРАВИЛАВзрослые / бизнес

09Правила работы с ИИ

Шаблоны задач, критерии проверки, границы данных и инструкции для повторного использования.

01ЗадачаПеревести разрозненные удачные промпты в управляемую операционную систему.

02Роль ИИПомогает формализовать повторяемые шаблоны, проверки и варианты исполнения.

03Проверка человекомФиксирует права, данные, ответственность и правила эскалации.

04Готовый результатРегламент + шаблоны задач + правила проверки + заметки об управлении.
